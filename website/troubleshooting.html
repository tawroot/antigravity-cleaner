Error 403 Forbidden • Sanction Gate

"Service is not available in your country" / Region Lockout

Target: main.js, agy CLI, extension.js, Antigravity core • Affected Regions: Iran, Russia, China, Cuba, Syria

Root Cause: Google Antigravity enforces client-side eligibility gate checks inside the Electron wrapper, the CLI daemon, and the internal VS Code extensions alongside upstream Geo-IP header verification. When an unsanctioned IP or region code is detected, Antigravity revokes the active session and forces a redirect to the login screen.

HTTP 403 Forbidden: Your current account is not eligible for Antigravity, because it is not currently available in your location.
Verified Resolution:
  1. Neutralize Client-Side Gatekeeper: Run ag-cleaner patch all (or click [Auto-Fix] in GUI). This overrides the isGoogleInternal and region authorization functions across all 4 software targets.
  2. Launch via Isolated Loopback Socket: Run ag-cleaner launch. This passes --proxy-server=socks5://127.0.0.1:<port> directly to the process, routing only the IDE through your local VPN while keeping the rest of your system on direct high-speed internet.
  3. Avoid Global TUN Mode: TUN adapters route whole-system traffic, induce MTU packet fragmentation, and trigger Middlebox DPI disconnections.
Error 429 • Rate Limit / Quota Bucket Corrupted

"Too Many Requests" & Artificial Quota Freeze

Affected Files: ~/.config/Antigravity/Cache, DawnWebGPUCache, quota_state.json

Root Cause: Autonomous agents generate rapid bursts of tool invocations, bash executions, and transcript logging. When local token tracking records become desynchronized from Google Cloud's upstream quota counters, the client freezes in a persistent 429 state even after waiting out the quota window.

Error 429: Resource has been exhausted (e.g. check quota). Too Many Requests.
Surgical Reset Guarantee (Zero Chat Loss):
  1. Click [Reset 429] in the Retro GUI or run:
    ag-cleaner clean
  2. Zero Data Loss: Unlike crude scripts that delete the entire globalStorage directory, Antigravity Cleaner surgically targets only 16 corrupted telemetry and rate-limit cache files. Your cookies, active Google login, and workspace chat archives are 100% preserved.

Authentication Block • 403 That's An Error

"403. That's an error. /auth-success"

Target: OAuth 2.0 Loopback Redirect Callback
📸 Visual Proof: Google Accounts blocking OAuth callback with 403 Forbidden on /auth-success.

Root Cause: When authenticating via the browser, Google checks the IP address of the local loopback redirect. If your browser routes the callback without proxy encapsulation or with mixed DNS resolution, Google flags the request as coming from an unauthorized geographic zone.

Instant Fix:

Run ag-cleaner patch all. Antigravity Cleaner patches core authentication flags (enforcing enterprise token mode) and purges tainted browser session cookies. Ensure your web browser uses the exact same proxy or clean DNS when completing the sign-in modal.

Startup Lockout • Dead PID Singleton

Antigravity Won't Open After System Sleep or Force Quit

Target: ~/.config/Antigravity/SingletonLock • Linux / macOS

Root Cause: If your system suspends, hibernates, or the IDE is terminated abruptly, Chromium leaves an orphaned lockfile at ~/.config/Antigravity/SingletonLock pointing to a dead PID. Subsequent launches detect the lockfile, assume another instance is running, and exit immediately without rendering a window.

# Manual Terminal Fix: rm -f ~/.config/Antigravity/SingletonLock ~/.config/Antigravity/SingletonSocket ~/.config/Antigravity/SingletonCookie

Automated Guard: ag-cleaner launch automatically inspects and cleans stale singleton locks prior to launching the IDE every time!
