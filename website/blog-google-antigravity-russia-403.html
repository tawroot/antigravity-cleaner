Google Antigravity в России: Как обойти ошибку 403 и настроить V2Ray без TUN

Инженерный разбор геоблокировок Google DeepMind: почему Antigravity вылетает с ошибкой «Account not eligible» даже с VPN, и как запустить среду разработки через точечный SOCKS5 прокси.

Автономная среда разработки Google Antigravity — один из самых мощных инструментов программирования на базе моделей нового поколения. Однако российские разработчики сталкиваются с непреодолимым барьером при попытке входа или генерации кода:

HTTP 403 Forbidden: "Your current account is not eligible for Antigravity, because it is not currently available in your location."

Многие пытаются решить проблему включением глобального TUN-режима в клиентах V2RayN, Hiddify, Clash Verge или NekoBox. Однако через 10–15 минут работы генерация кода зависает, соединение сбрасывается (ECONNRESET), а сессия аккаунта сбрасывается в разлогин.

1. Почему стандартный VPN не работает стабильно

Google Antigravity использует гибридную клиент-серверную проверку локации:

  • Локальные скрипты валидации: Внутренние файлы Electron (main.js, вспомогательный бинарный демон agy и extension.js) выполняют превентивную проверку системных переменных окружения.
  • Сброс сессий узлами ТСПУ (DPI): Длинные стримы рассуждений LLM передаются по протоколу HTTP/2 multiplexed streams. При включенном общем VPN и кратковременном простое (пауза между токенами 10–20 секунд) фильтрующее оборудование провайдера посылает пакет TCP RST, разрывая сессию.
  • Утечка DNS через системный шлюз: Если ОС отправляет хотя бы один запрос к доменам Google напрямую через провайдерский DNS, бэкенд Google мгновенно помечает сессию как недопустимую.
Архитектурный вывод: Включать глобальный TUN-режим для всей операционной системы — неэффективно и рискованно. Гораздо надежнее изолировать процесс Antigravity и направить только его через локальный SOCKS5 loopback порт (127.0.0.1:10808).

3. Запуск без TUN-режима: инъекция параметров в процесс

Поскольку Antigravity работает на базе Electron, ему можно напрямую передать флаги управления сетевым стеком Chromium, оставив весь остальной трафик системы прямым и быстрым.

Linux (Bash):

# Запуск Antigravity через активный порт V2Ray (10808)
antigravity \ --proxy-server="socks5://127.0.0.1:10808" \ --host-resolver-rules="MAP * ~NOTFOUND , EXCLUDE 127.0.0.1" \ --no-sandbox

Windows (PowerShell):

# Настройка переменных окружения для воркеров Node.js
$env:ALL_PROXY = "socks5://127.0.0.1:10808"
& "$env:LOCALAPPDATA\Programs\Antigravity\Antigravity.exe" --proxy-server="socks5://127.0.0.1:10808"

4. Автоматическое решение в 1 клик: Antigravity Cleaner

Утилита с открытым исходным кодом Antigravity Cleaner полностью автоматизирует этот процесс:

  1. Патчинг ядра: Нейтрализует клиентские гео-проверки в main.js и agy, предотвращая разлогин аккаунта Google.
  2. Автоопределение порта: Сканирует локальные сокеты и находит запущенный клиент (V2Ray на 10808, Clash на 7890 или NekoBox на 2080).
  3. Активный KeepAlive (15 сек): Посылает проверочные пакеты в туннель, исключая тайм-ауты и сбросы сессий провайдерскими ТСПУ.
  4. Создание ярлыка: Создает ярлык запуска на рабочем столе с уже прописанными сетевыми аргументами.
# Установка для Linux / macOS:
curl -sSL https://raw.githubusercontent.com/tawroot/antigravity-cleaner/main/install.sh | bash

# Автоматический запуск через рабочий прокси:
ag-cleaner launch

Команда установки в Windows (PowerShell от имени администратора):

irm https://raw.githubusercontent.com/tawroot/antigravity-cleaner/main/install.ps1 | iex
ag-cleaner launch
